# Medcore HMS API reference

The interactive API reference is generated by NestJS Swagger from the running application.

- Local Swagger UI: `http://localhost:3000/api/docs`
- Local OpenAPI JSON: `http://localhost:3000/api/docs-json`
- Production Swagger UI (after the Swagger-enabled backend deployment): `https://medcore-api.duckdns.org/api/docs`

## Authentication

Protected routes use a JWT access token:

```http
Authorization: Bearer <accessToken>
```

Obtain the access token from `POST /auth/login`. It expires after 15 minutes. Login also sets the `medcore_refresh` HttpOnly cookie. The browser must send credentials when calling `POST /auth/refresh` and `POST /auth/logout`; client-side JavaScript cannot read the HttpOnly cookie.

In Swagger UI, select **Authorize** and paste only the access token value. Refresh and logout depend on the browser's cookie handling and may need to be tested from the deployed/local frontend or an HTTP client with a cookie jar.

## Endpoint groups

The following groups are derived from the controllers currently registered in `AppModule`. For exact request DTO fields, response shapes, and route parameters, use the generated Swagger UI.

| Group | Base path | Main capabilities |
|---|---|---|
| Authentication | `/auth` | Register, verify email, resend OTP, login, refresh, logout, profile |
| Hospital registration | `/hospitals/register` | Submit a hospital registration request |
| Hospitals | `/hospitals` | Create/list hospitals, list verified hospitals, verify or reject |
| Departments | `/hospitals/:hospitalId/departments`, `/departments` | Create, list, update, activate/deactivate |
| Doctors | `/hospitals/:hospitalId/doctors`, `/doctors` | Create, list, view, update, activate/deactivate |
| Staff | `/staff` | Create/list staff and update account status |
| Users | `/users` | Platform user listing, details, and status management |
| Availability | `/doctors/:doctorId/availability` | Weekly schedules and available slots |
| Appointments | `/appointments` | Book, list own/doctor appointments, view and change appointment status |
| Hospital dashboard | `/hospital-dashboard` | Overview, appointments, patients, patient records |
| Platform analytics | `/platform-analytics` | Platform overview with date filters |
| Medical records | `/medical-records` | Create/update/finalize records, vitals, patient history |
| Patient allergies | `/patient-allergies` | Create, view, update, and deactivate patient allergy records |
| Prescriptions | `/prescriptions` | Create, list patient prescriptions, medicine search, PDF export |
| Laboratory | `/lab` | Tests, orders, sample collection, processing, result upload and approval |
| Pharmacy | `/pharmacy` | Medicine catalogue, stock, batches, dispensing |
| Billing | `/billing` | Invoices, manual payments, Razorpay order/verification, PDF |
| Notifications | `/notifications` | List, mark one read, mark all read |
| Razorpay webhooks | `/billing/webhooks/razorpay` | Verify and process payment-provider webhook events |

## Common response format

Most JSON endpoints return:

```json
{
  "success": true,
  "data": {},
  "message": "Request completed successfully"
}
```

Validation and HTTP errors are normalized to:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "A human-readable explanation"
  }
}
```

Binary PDF endpoints and a small number of domain endpoints can return a non-envelope response; check the operation's response content type in Swagger.

## Role model

The API uses these roles: `SUPER_ADMIN`, `HOSPITAL_ADMIN`, `DOCTOR`, `NURSE`, `RECEPTIONIST`, `LAB_TECHNICIAN`, `PHARMACIST`, `ACCOUNTANT`, and `PATIENT`.

Authorization is enforced server-side. A frontend route being visible does not grant API access. Always test protected operations with the appropriate role and a user belonging to the relevant hospital.

## Payment webhook

The Razorpay webhook endpoint validates the raw request body using the `x-razorpay-signature` and `x-razorpay-event-id` headers. Configure the same webhook secret in the backend environment and Razorpay dashboard. Do not call this endpoint as a normal browser operation.

## Important

This API manages sensitive patient and clinical information. Use synthetic records in development and test environments. Do not publish access tokens, refresh cookies, SMTP credentials, Razorpay secrets, or real patient data in issues, logs, or screenshots.
